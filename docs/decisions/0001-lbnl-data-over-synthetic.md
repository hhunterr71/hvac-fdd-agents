# Use LBNL FDD data instead of a home-built simulator

The proposal planned synthetic VAV telemetry. We use the public LBNL FDD Data Sets (CC-BY) as the primary data instead, so results are on a third-party benchmark rather than data we wrote ourselves. Detection ground truth comes from Symptom Windows, found by comparing each faulted Fault Case against its Fault-free Twin, because LBNL labels say a fault is present all year even when it can't be seen.

The data is kept to what a real project would hand over: trend CSVs (one fault-free twin plus one file per Fault Case) and one hand-tagged Haystack points config per system, which serves as the Reference Mapping. LBNL's Brick `.ttl` files and Building 59 are not used, because real projects don't arrive with Brick models, and LBNL's 109 cryptic point names per system are enough to test the tagging agent. Fault labels (faulted unit, fault type, severity) live in a separate cases file that only the scorer reads.

## Consequences

- No synthetic or rearranged data at all, including no splicing of cases together. With nothing to re-run, a fix can't be shown to work, so the scored chain stops at Dispatch: Detect → Diagnose → Dispatch. The Verifier/closure loop and the Fault Author agent are cut.
- Each Fault Case is scored on its own. Fault-free cases score Unnecessary Dispatches.
- Depends on faulted and fault-free cases sharing timestamps, weather, and schedules. Verified 2026-10-13 on the PFPU fault-free and damper-stuck-20% files: 525,600 identical minute timestamps for 2018, and identical OA_TEMP.
- Each Fault Case is a small connected system: one AHU plus four fan-powered VAV terminals (zones I, W, S, E), with a fault in one terminal. The fault shows up in the AHU (SA_CFM, SF_WAT) and slightly in the healthy terminals, so "the unit that differs from its twin" is not trivially "the faulted unit."
- Data quality: the LBNL inventory says faults are always in zone W, but comparing each case with its twin (benchmark/ground_truth/find_faulted_zones.py, 2026-10-13) puts the fault in zone S in 54 of 60 PFPU/SFPU cases, often by 10–100× over the other zones. The remaining 6 (waterside reheat coil fouling, all severities) show no zone-level divergence at all and are assumed to be S as well. Ground truth records VAV-S, not the documented W.
- The ORNL lab RTU and field RTU cases have no time-aligned twin (each fault covers different days from its fault-free file), so they support only case-level scoring, not Symptom Windows.
- Labels for all 310 files live in benchmark/ground_truth/catalog.csv, built from the LBNL inventory PDFs and checked against the data. The inventories contain errors the catalog corrects and notes: the wrong zone for every fan-powered VAV fault; dual-duct AHU box faults are in zone SA; dual-duct OA damper severities and static pressure bias units disagree between tables; a fan coil cooling-valve leak is labeled as heating; the single-duct AHU sensor bias files are named coi_bias, not sa_bias; and the chiller fouling files aren't listed at all. In the single-duct AHU sensor bias cases, the logged temperature is the true value, not the biased reading, so the fault shows only through the controller's response.
